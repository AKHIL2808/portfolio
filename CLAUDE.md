# CLAUDE.md

## Project context

**Midnight to Dawn**: Akhilesh Singh's scroll-driven 3D portfolio, themed on the anime Demon Slayer and told as one continuous camera journey in 8 acts (Act 0 Loading → Act 7 Mansion), plus a fast plain-HTML recruiter page at `/cv`. Built solo.

- **Blender first, always.** Every shot is built, rendered and **approved in Blender** before any web code plays it. The browser plays exactly what Blender shows.
- The work unit is **one shot** (or a set/scaffold, a transition, or a cast member). Each shot has two phases, done in separate sessions: **Blender phase** (build → render → approve → export) then **Web phase** (code → test → stitch).
- Acts and pages: 0 Breath (Loading) · 1 The Fall (Home) · 2 The Quiet Room (About) · 3 The Battlefield (Skills) · 4 The Upper Ranks (Projects) · 5 The Demon King (Experience) · 6 Dawn (transition) · 7 The Mansion (Contact).
- Out of scope for v1: multiplayer or visitor accounts, a CMS, multiple languages.
- The repo starts with only `docs/`. Do not assume any code, script, `package.json` script or Blender file exists until the build-order item that creates it is ticked.

### Source documents (in `docs/`)

| Doc | File | Authority |
|---|---|---|
| Director's Implementation Plan | `docs/plan.md` (else `docs/Midnight to Dawn — Director's Implementation Plan.pdf`) | **Build order and every shot's Director's view, Blender / Code / Test checklists.** Shot ids come from here. |
| Technical Design Document | `docs/tdd.md` (else `docs/Midnight to Dawn — Technical Design Document.pdf`) | **Architecture, stack, budgets, rules.** Source of truth for anything technical. |
| Screenplay | `docs/screenplay.md` (else `docs/Midnight to Dawn — Demon Slayer Portfolio Screenplay.pdf`) | The story, sound motifs, color script, original-design notes. |
| Progress log | `docs/progress.md` | Done, next, open issues. Updated at the end of every task. |

Read a PDF with `pdftotext -layout "<file>" -` when its `.md` version doesn't exist yet. If the docs disagree: the plan wins on build order and shot content, the TDD wins on architecture, budgets and libraries; anything else, ask. (Known difference: the screenplay and TDD milestones build Act 7 and Act 4 before Act 3; the plan builds acts in order. We follow the plan; building out of order only gives a warning.)

**Where things belong:**
- Assets only flow `blender/` → `raw-assets/` → `scripts/optimize-assets.mjs` → `public/`. Nothing reaches `public/` unoptimized; nothing in `public/models` or `shots/` camera keys is hand-edited.
- The only files you edit to change the story are `shots/*.json` (events and gates; camera keys come from Blender) and `content/*.ts` (portfolio text).
- The Director is the only thing that changes the current act. At most 2 acts are mounted.
- No act imports another act. Shared code goes in `systems/`, `characters/`, `materials/`, `vfx/` or `ui/`.
- Phase-specific rules live in `.claude/rules/blender.md` (loaded for `blender/**`) and `.claude/rules/web.md` (loaded for `src/**`, `content/**`, `shots/**`, `tests/**`).

## Naming

- **Shot ids** match the plan and are used everywhere: Blender markers, shot JSON entries, test names, branches, commits, `docs/progress.md`.
  - Shots `1.5`, set/scaffold `1.0`, transitions `T0→1` (marker `T01`, hand-off marker `T01-handoff`).
  - Pillar sequence `3<P>-A … 3<P>-G`, with Pillar codes **K** Kaname · **M** Minato · **Ki** Kiri · **Ho** Homura · **Hi** Hibiki · **I** Iwao (e.g. `3K-B`, `3Ho-D`).
  - Upper Rank fight `4R<n>-A … 4R<n>-F`, Rank Six first (`4R6-A`); the clash's cuts are markers `4R<n>-C1..C3`.
  - Demon King phase `5K<n>-A … 5K<n>-E`, one `<n>` per `content/experience.ts` entry, oldest first.
  - Foundation `F.1 … F.4`, cast `C1 … C9` (plan's build-order table) and `CP` (shared props), final assembly `Z.1 … Z.6`.
- **Build-order item ids** are `<unit>/<phase>`: `B` = Blender phase, `W` = web phase (code + test). Big units split into `<unit>/<phase>.<nn>`. Examples: `1.5/B`, `1.5/W`, `T0→1/B`, `3K-D/W`, `C1/B.03`, `F.3/W.07`.
- **Slugs:** lowercase, `.` `/` `→` become `-`. The **item slug** names branches and specs (`1.5/B` → `1-5-b`, `T0→1/W` → `t0-1-w`); the **unit slug** names renders and shot tests (`1.5` → `1-5`: `blender/renders/stills/1-5/`, `blender/renders/previews/1-5.mp4`, `tests/e2e/shots/1-5.spec.ts`).
- Blender: collections `act<N>_<thing>`, actions `<character>_<move>` (loops end `_loop`), set files `blender/scenes/act<N>-<name>.blend`, bridges `blender/scenes/bridge_<from>-<to>.blend`.
- Web: components PascalCase, hook files start with `use`, one act per folder, shaders in `*.glsl.ts`.

## Code style

- TypeScript strict, no `any`, functional components. ESLint with React hooks rules, no unused code.
- Next.js App Router. The 3D experience is client-only; `/cv` is statically generated with no WebGL and no animation library.
- **React stays out of the frame loop:** no `useState`/`setState` per frame, no allocations inside `useFrame`; read the store with `useStore.getState()`; animate through `useActFrame((state, scaledDelta) => …)` so slow motion works.
- Camera only moves through refs inside `useFrame`, never through React state. Parallax and shake are added on top of the shot pose, never baked in.
- Shaders: exported template strings in `.glsl.ts`, built by extending three.js materials (`onBeforeCompile` or a shared chunk) so skinning, morph targets and instancing keep working. One material per effect type; per-instance differences in instance attributes; animate by uniforms only.
- Content: every `content/*.ts` file has a zod schema in `src/lib/schemas.ts`; the build fails on invalid content.
- Readable text is real HTML, placed on 3D surfaces with drei `<Html transform occlude>`.
- Python (`bpy`) scripts: idempotent, re-runnable headless, fixed seeds, every scene script calls `settings.py` first, no hard-coded localized node names or enum identifiers.

## Preferred libraries

Install the latest stable version of each at setup (F.1) and pin exact versions in `package.json`. Don't upgrade majors mid-build. **Do not add any library not listed here without asking first.**

| Layer | Use |
|---|---|
| 3D authoring | Blender (latest stable), Rigify, Blender MCP server (live) + saved `bpy` scripts (headless) |
| Framework | Next.js (App Router) + TypeScript strict, Tailwind CSS |

| Animation / scroll | GSAP + ScrollTrigger, Lenis |
| State / data | Zustand, zod |
| Audio | Howler.js (audio sprites) |
| Device | detect-gpu |
| Email | Resend |
| Asset tools | gltf-transform CLI (meshopt), KTX-Software (KTX2), SVGO |

## The shot loop (workflow)

```
/build-order <stage>                 # once per stage: tickable checklist from docs/plan.md
/create-spec <shot> blender          # spec + branch shot/<slug>-b      → Plan Mode → approve plan
/blender-shot <shot>                 # build live via Blender MCP, save to bpy script, headless rebuild, review
/approve-shot <shot>                 # render stills + preview, YOU approve, record approval, export
/ship-shot                           # tick <shot>/B, commit, PR, squash-merge
/create-spec <shot> web              # only after <shot>/B is approved  → Plan Mode → approve plan
   …implement…
/test-shot <shot>                    # test writer, then test runner (unit, parity, stitch, budgets)
/review-shot <shot>                  # quality + performance reviewers in parallel (+ security when relevant)
/ship-shot                           # tick <shot>/W, commit, PR, squash-merge
```

Framing and timing problems are always fixed in Blender and re-exported; code problems are fixed in code. A shot is never left with a known jump into the next one.

## Commands

```bash
pnpm dev | pnpm build | pnpm typecheck | pnpm lint
pnpm test                        # Vitest: content schemas, shot data, systems
pnpm test:e2e                    # Playwright: flow, parity, fallbacks

```

These `pnpm` scripts don't exist until F.1/F.2 create them. CI (GitHub Actions) runs typecheck, lint, unit tests, e2e and Lighthouse on every push; a failing check blocks merging into `main`. Dev pages: `/dev/shot?shot=1.5&t=0.5` (freeze any moment, VFX off, fixed seed), `/dev/stitch?from=1.4&to=1.6` (loop a range), `/dev/character`.

## Subagent policy

- Use a built-in Explore subagent for codebase exploration before implementing a new shot's web phase.
- Use `mtd-blender-reviewer` after every Blender build, before asking for render approval.
- Use `mtd-test-writer` then `mtd-test-runner` after every web implementation (`/test-shot`); the runner's VERIFIED is what "verified by a subagent" means.
- Use `mtd-quality-reviewer` and `mtd-performance-reviewer` in parallel for every web phase (`/review-shot`); add `mtd-security-reviewer` whenever the change touches the contact route, forms, headers, env or dependencies.
- When asked to plan, delegate research to a subagent before presenting the plan. Use the built-in Plan subagent in plan mode.

## Critical rules

- **Blender first.** No web code for a shot until its `<shot>/B` item is ticked and the shot has a row in `blender/renders/APPROVALS.md`. An act is only exported after its preview render is approved.
- **Only the user approves a render.** Never record an approval on your own judgment.
- **Reproducible Blender.** Every change made live through the Blender MCP is also saved in a `bpy` script in `blender/scripts/`, and the scene rebuilds from scratch with `blender --background --python …`. If a `.blend` breaks, nothing is lost.
- **Parity.** Every shot passes the parity test (Blender still vs `/dev/shot` screenshot, similarity ≥ 0.90; otherwise a diff image is saved). Parity settings (meters, Y up, AgX, sRGB/Non-Color, 30 fps, 1920×1080, fixed seeds) are set once in F.2 and never changed per shot.
- **Not exportable:** particles, simulations and compositor effects. Keep a simple VFX proxy in Blender for timing and framing; approve the real effect in the browser.
- **Budgets** (docs/tdd.md › Performance and › Characters): stay within triangles, bones, textures, draw calls and asset budgets per tier. A feature that breaks a budget is simplified in Blender (fewer triangles, smaller textures, a LOD) before it is cut. An act isn't done until it meets its tier budgets.
- **Content-driven:** all portfolio text in `content/`; adding a project, skill or experience entry must need no 3D code change.
- **Recruiter-safe:** name and role visible within 3 s, every act skippable, `/cv` always one click away, no sound before the Enter click, mute reachable from the first screen.
- **Accessibility:** every interaction has a keyboard path; the canvas is `aria-hidden="true"`; no flashing faster than 3 times per second; reduced-motion mode replaces camera flights with 0.6 s crossfades.
- **Original art only:** characters, demons and environments are original designs in the anime's spirit; no copied characters, crests, music or voices. Every third-party asset's license goes in `raw-assets/LICENSES.md`.
- **Secrets:** `RESEND_API_KEY` and `CONTACT_TO_EMAIL` only in Vercel env vars and a git-ignored `.env.local`; keep `.env.example` in sync. Never render visitor input as HTML.
- **No new dependencies** without asking first.
- **Git LFS** for `.blend`, `.png`, `.exr` (and raw textures/audio).
- **Before finishing a task:** run typecheck, lint and tests, and fix failures. At the end of each task, update `docs/progress.md` (done, next, open issues).
- **Build-order files:** each stage has a checklist in `.claude/build-order/stage-<S>.md`, generated by `/build-order <S>`. Build its items in file order; tick `- [ ]` → `- [x]` only when the item's *Done when* passes (for `/B` items that includes your approval). A stage is completed only when every item is ticked.
- **One phase per session.** A Blender session and a web session for the same shot are separate; each starts in plan mode with a reviewed plan.
